# Corrections to the rules

Dated 2026-10-01. These are newer than terminology-script-asst.md. Where the two differ, this file wins.

1. **Do not write `migrated-to` pointers, and do not edit the Brain Dump doc at all.** A separate script writes the pointers after your work is checked.
2. **End your run log with a unit record.** For each unit you migrated, list the source line or lines it came from, and the note each copy went to.
3. **When one bullet is split across notes, each piece carries the context it needs to make sense in its own note.** Repeating a fact that also sits in another note is fine. When unsure, keep the context.
4. **When one status tag sits on a bullet that holds several ideas, the tag covers only the idea it clearly belongs to.** An idea in that bullet that the writer worded as a possibility stays where it is. Name those ideas in the run log and ask the writer whether the tag covers them.
5. **The Rejected section holds only the rejected unit and the writer's reason for rejecting it.** What a comment says to keep stays in the live part of the note. Do not write up the carve-out under Rejected. If the rejection leaves a neighbouring line ungrammatical, fix that word.
